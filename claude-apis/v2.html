What changed since April 2026

Several statements in the earlier version of this page no longer hold. Corrections first, then new capabilities.

Correction

The Compliance API can read content Fix

With the read:compliance_user_data scope it returns chats, messages, uploaded files, projects and session transcripts. With delete:compliance_user_data it hard-deletes chats, files and projects. Only the Activity Feed is metadata-only.

Correction

No NDA gate for the Compliance API Fix

Docs are public on platform.claude.com. The primary owner enables it self-service in claude.ai and creates a scoped Compliance Access Key. The read:security key type is gone.

Correction

Analytics lag is 1 day, range up to 366 days Fix

Enterprise engagement data lands around 13:00 to 13:30 UTC the next day. History still starts 1 Jan 2026. The endpoint set grew from 5 to 11, adding Cowork, plugins and artifacts.

29 Oct 2026

Usage and Cost Analytics API Beta

New /analytics/usage and /analytics/cost for both Console and Enterprise. The old Usage and Cost API and the four Enterprise report endpoints are now legacy but supported.

Aug to Oct 2026

Session transcripts in Compliance New

Local and remote sessions for Claude Code, Cowork and Claude for Microsoft 365 are stable. Claude in Chrome, Google Workspace add-ins, Claude Science and Claude Tag are in beta.

20 Oct 2026

Inference hooks GA for Enterprise New

Anthropic posts each request to your AI security server for an allow or deny verdict before the model runs. This is the first inline, blocking control. Everything else on this page is after-the-fact.

5 Nov 2026

Security posture endpoint Beta

Returns pass, fail or not-attested ratings per org control. The Admin API can also sign a member out everywhere (beta).

24 Sep 2026

File names removed from Activity Feed Change

File, project-document and artifact events no longer carry names or titles. Exfiltration rules that keyed on file names need to join on IDs via the content endpoints.

30 Sep 2026

Admin API out of beta in SDKs New

Members, invites, workspaces, API keys, rate limits, service accounts, workload identity federation, CMEK and compliance settings. Org webhooks entered beta on 20 Oct but do not deliver events yet.

Who can see prompts and responses

The most consequential difference for works councils, DPOs and privacy reviews. Three tiers.

A Compliance Access Key with user-data scope is a key to every conversation in the org

Treat it like a domain admin credential: vault it, scope it to the minimum (Activity Feed only needs read:compliance_activities), issue separate keys for SIEM and eDiscovery, and alert on compliance_api_accessed. Keys never expire on their own. In Germany, reading employee content usually triggers Betriebsrat (works council) co-determination under BetrVG §87(1) Nr. 6 (Works Constitution Act, rule on technical monitoring of employees), so agree the scope in a Betriebsvereinbarung (works agreement) before enabling content scopes.

Full content, by design
ComplianceInference hooks

Compliance reads stored chats, files and transcripts after the fact. Inference hooks receive every governed request in real time and can block it.

Content only if you opt in
CC OTel

OTEL_LOG_USER_PROMPTS, OTEL_LOG_ASSISTANT_RESPONSES, OTEL_LOG_TOOL_DETAILS, OTEL_LOG_TOOL_CONTENT and OTEL_LOG_RAW_API_BODIES are all off by default.

Inference hooksCompliance

SIEM ingestion pattern

Poll the Activity Feed on a closed time window that ends at least one minute in the past, overlap windows, and deduplicate on id because delivery is at-least-once. Splunk, Datadog, Sentinel and Cribl are the documented examples.

Python sketch: Activity Feed poller
# Minimal poller. Check cursor semantics against the API reference before production use.
import os, time, requests
from datetime import datetime, timedelta, timezone

BASE = "https://api.anthropic.com/v1/compliance/activities"
HDRS = {"x-api-key": os.environ["CLAUDE_COMPLIANCE_KEY"],  # read:compliance_activities only
        "anthropic-version": "2026-10-21"}
seen = set()                                 # persist in production

def poll(window_start):
    end = datetime.now(timezone.utc) - timedelta(minutes=2)   # lt must be >= 1 min in the past
    params = {"created_at.gte": window_start.isoformat(),
              "created_at.lt": end.isoformat(), "limit": 1000}
    while True:
        r = requests.get(BASE, headers=HDRS, params=params, timeout=30)
        if r.status_code == 429:
            time.sleep(10); continue
        r.raise_for_status()
        page = r.json()
        for ev in page["data"]:
            if ev["id"] not in seen:
                seen.add(ev["id"]); ship_to_siem(ev)
        if not page.get("has_more"):
            return end - timedelta(minutes=5)       # next window overlaps by 5 min
        params["after_id"] = page["last_id"]

High-value alert rules to start with

  • org_compliance_api_settings_updated: someone toggled the audit trail itself.
  • compliance_api_accessed from an unexpected key or outside the SIEM's IP: someone is reading content.
  • claude_organization_settings_updated where retention periods changed.
  • inference_hooks_circuit_breaker_tripped: your DLP gate is failing open or closed.
  • Spikes in claude_file_uploaded per actor, compared with that actor's 30-day baseline.

Rollout order

For a new Enterprise tenant. Steps 1 to 3 cannot be done retroactively, so do them before users arrive.

  1. Enable the Compliance API at the parent org on day one. Recording starts at enablement and cascades to linked claude.ai and Console orgs. Note that enabling it blocks browser-side direct Claude API calls for those orgs.
  2. Verify domains, connect SSO, turn on SCIM, restrict org creation. This stops shadow Team and Pro workspaces on your domain.
  3. Push Claude Code managed settings that force Enterprise login and set OTel exporters, so Code sessions land in Compliance transcripts and your collector.
  4. Issue least-privilege keys: one read:compliance_activities key for the SIEM, a separate user-data key held by legal or eDiscovery, one read:analytics key for FinOps.
  5. Set retention to match legal hold and storage-limitation policy, and document it in the record of processing.
  6. Add inference hooks in shadow mode, tune DLP verdicts on real traffic, then switch to enforcing with a deliberate fail-open or fail-closed choice.
  7. Build dashboards from Enterprise Analytics (adoption, dormant seats) and Usage & Cost Analytics (chargeback by RBAC group).
